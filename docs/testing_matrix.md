给《萌灵小岛》建立双端统一回归基线，明确区分：

- 脚本检查：文件、关键 token、基础工程结构
- 场景检查：场景能否打开、节点引用是否完整、资源是否可加载
- 真实运行检查：通过 Godot 编辑器实际运行并完成最小交互路径

## 5. 每次任务完成后的最小验证要求

### A. 脚本检查（必做）

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-project.ps1
```

### B. 场景检查（建议）

- 用 Godot 编辑器打开 `project.godot`
- 确认主场景 `res://scenes/world/test_world.tscn` 可加载
- 确认新增 Resource / Autoload 无丢失引用

### C. 真实运行检查（优先争取）

1. 用 Godot 4.x 编辑器打开项目。
2. 运行主场景 `res://scenes/world/test_world.tscn`。
3. 验证以下最小路径：
   - 玩家可移动
   - 可与 NPC 交互
   - 可从 `test_world` 切到 `grove_gate`
   - 可从 `grove_gate` 返回
   - 返回后出生点正确
4. 如果本次任务涉及 DisplayManager / 响应式 UI / 相机，额外验证：
   - 强制手机档位
   - 强制桌面档位
   - 查看 profile 日志或调试输出是否符合预期

## 6. 当前人工运行约定

在 CLI 无法直接启动 Godot 的前提下，暂按以下原则记录运行结论：

- “检查通过”：指 PowerShell 检查脚本通过
- “场景可读”：指工程文件、资源路径、Autoload 配置静态检查正确
- “真实运行通过”：仅在 Godot 编辑器里人工跑过后才可标记
- 若当轮未实跑，最终说明中必须明确写出“未完成真实运行确认”
