# 测试矩阵

## 1. 测试目标

给《萌灵小岛》建立双端统一回归基线，明确区分：

- 脚本检查：文件、关键 token、基础工程结构
- 场景检查：场景能否打开、节点引用是否完整、资源是否可加载
- 真实运行检查：通过 Godot 编辑器实际运行并完成最小交互路径

## 2. 当前验证能力状态

| 项目 | 当前状态 | 说明 |
| --- | --- | --- |
| 静态工程检查 | 已具备 | `scripts/check-project.ps1` 检查文件、关键节点、地图布局与基础规则。 |
| Godot CLI 运行时回归 | 已具备 | `scripts/run-regression.ps1` 覆盖世界、对话输入、存档、数值、五分辨率 UI、设置音频与战斗契约。 |

## 5. 每次任务完成后的最小验证要求

### A. 脚本检查（必做）

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-project.ps1
```

### B. 场景检查（建议）

- 用 Godot 编辑器打开 `project.godot`
- 确认主场景 `res://scenes/world/test_world.tscn` 可加载
- 确认新增 Resource / Autoload 无丢失引用

### C. 真实运行检查（优先争取）

1. 用 Godot 4.x 编辑器打开项目。
2. 运行主场景 `res://scenes/world/test_world.tscn`。
3. 验证以下最小路径：
   - 玩家可移动
   - 可与 NPC 交互
   - 可从 `test_world` 切到 `grove_gate`
   - 可从 `grove_gate` 返回
   - 返回后出生点正确
4. 如果本次任务涉及 DisplayManager / 响应式 UI / 相机，额外验证：
   - 强制手机档位
   - 强制桌面档位
   - 查看 profile 日志或调试输出是否符合预期

## 6. 当前人工运行约定

- “静态检查通过”：`scripts/check-project.ps1` 成功结束。
- “CLI 运行时回归通过”：`scripts/run-regression.ps1` 输出 `REGRESSION_SUITE_OK`。
- “编辑器人工回归通过”：在 Godot 窗口内完成新建存档→向导赠送→六地区收服→云台完成总结→重启恢复的路径。
- CLI smoke 不替代人工操作；涉及移动手感、真实输入热区、场景转场和 Android 触控时，最终说明必须标出人工验收状态。
