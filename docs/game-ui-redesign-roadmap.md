# 萌灵小岛游戏化 UI 长期改造计划

> 建立日期：2026-07-24  
> 设计基准：1280×720 横屏  
> 实施原则：保留现有玩法、存档和数据接口，分阶段替换表现层，每阶段均可独立验收和回退。

## 1. 背景与目标

当前世界地图已经具备较强的游戏场景感，但图鉴、小屋、栖息地、遇敌准备等页面仍主要由大面积 `PanelContainer`、`ItemList`、长文本和横向大按钮组成，视觉结果接近桌面管理界面。此次改造目标是建立统一的游戏化 UI 语言，并按页面逐步迁移。

长期目标：

- 世界地图保持最大可视面积，HUD 只呈现必要信息。
- 图鉴体现发现、收集、未知剪影和萌灵信息浏览体验。
- 小屋突出萌灵角色、照料反馈和状态变化，而不是数据列表。
- 弹窗、按钮、卡片、状态条和关闭方式形成统一组件规范。
- 桌面 1280×720、1920×1080 和手机横屏均保持可读、可操作。
- 每次只重构一个可验证范围，不同时改动玩法公式、存档格式和 UI 表现。

## 2. 当前问题

### 2.1 共性问题

- 大面板占据接近全屏，地图失去空间层次。
- 半透明米白色叠加过多，文字和背景对比不足。
- `ItemList` 的整行灰色选中样式带有明显工具软件感。
- 信息主要依靠连续文字表达，缺少头像、图标、标签、进度条和反馈动画。
- 页面底部使用横跨全宽的“返回地图”按钮，占用空间且不符合常见游戏返回习惯。
- 图鉴、小屋使用相同的“左列表 + 右文字”模板，缺少功能身份。
- UI 节点集中在 `gameplay_ui.tscn`，后续维护和复用成本较高。

### 2.2 世界 HUD

- 左上区域标题偏大，长期遮挡地图。
- 右上入口按钮偏矩形工具栏风格。
- 缺少可自动隐藏的交互提示和页面打开时的背景遮罩层。

### 2.3 图鉴

- 萌灵以文本列表呈现，收集反馈弱。
- 已入住、已发现、未发现状态依赖文字前缀。
- 右侧没有大型立绘、属性徽章和栖息地信息分区。
- 未发现萌灵没有剪影和解锁提示。

### 2.4 小屋

- 萌灵列表和连续状态文本占据主要画面。
- 当前萌灵没有成为视觉中心。
- 亲密、饱腹、清洁没有独立进度反馈。
- 喂食、清洁、摸摸和休息操作缺少角色反馈动画与数值飘字。

## 3. 改造范围与不变范围

### 3.1 本计划包含

- 世界 HUD 的尺寸、层级和入口按钮。
- 通用游戏弹窗、遮罩、页头、关闭按钮、标签和卡片组件。
- 图鉴页面结构和交互表现。
- 小屋页面结构、状态展示和照料反馈。
- 栖息地、遇敌、战斗准备等次级弹窗的统一迁移。
- 横屏响应式布局、键盘/手柄返回、触控热区和视觉回归检查。

### 3.2 本计划不改变

- `SaveManager` 的存档字段和持久化格式。
- `GameState` 的页面状态语义，除非拆分组件所必需。
- `GameCatalog`、萌灵属性、照料数值和战斗公式。
- 世界地图 TileMap、玩家移动、场景出口和碰撞逻辑。
- 已接入的萌灵资源路径；允许新增 UI 专用缩略图或图标映射。

## 4. 目标信息架构

### 4.1 世界 HUD

- 左上：紧凑区域铭牌，建议宽 200–240px、高 48–56px。
- 右上：图鉴、小屋两个 56–64px 图标入口，文字作为短标签或 Tooltip。
- 底部：按情境出现的交互提示，默认隐藏。
- 页面打开：地图保留可见，增加 30%–45% 暗色遮罩，使弹窗与世界分层。

### 4.2 图鉴

- 页头：标题、发现进度、筛选标签、关闭按钮。
- 左区：三列萌灵头像卡片或可滚动网格。
- 右区：大型立绘、名称、等级、属性徽章、状态、描述、栖息地和喜好。
- 状态表达：入住使用小屋角标，已发现使用彩色头像，未发现使用剪影和问号。
- 返回方式：右上关闭按钮、`Esc`、手柄返回键；不使用全宽返回按钮。

### 4.3 小屋

- 页头：标题、当前拥有数量、关闭按钮。
- 左区或底部：伙伴头像轮播，不使用文本 `ItemList`。
- 中央：当前萌灵大立绘或待机动画。
- 右区：等级、HP、经验、亲密、饱腹、清洁、心情和最爱。
- 底部：喂食、清洁、摸摸、休息四个同尺寸图标操作按钮。
- 操作反馈：萌灵动作、短提示、数值飘字和对应进度条动画。

## 5. 通用视觉规范

| 项目 | 规范 |
| --- | --- |
| 设计画布 | 1280×720 |

| 主面板 | `#FFF9E9`，不透明，2–3px `#8B6842` 描边 |
| 主文字 | `#4A3B2C` |

| 主绿色 | `#76B947` |
| 能量蓝 | `#54AEDD` |
| 警告红 | `#D96157` |

| 页面返回 | 右上关闭、Esc、手柄返回；必要时保留小型文字按钮 |

## 6. 技术拆分方案

建议把 `gameplay_ui.tscn` 中的大型页面逐步拆分为独立场景：

```text
scenes/ui/
├─ gameplay_ui.tscn                 # 世界 HUD 与页面挂载点
├─ components/
│  ├─ game_modal_shell.tscn         # 遮罩、面板、页头、关闭按钮
│  ├─ spirit_portrait_card.tscn     # 萌灵头像卡
│  ├─ element_badge.tscn            # 属性徽章
│  ├─ stat_meter.tscn               # HP/经验/亲密/饱腹/清洁
│  └─ icon_action_button.tscn       # 图标操作按钮
├─ dex/
│  └─ dex_panel.tscn
└─ home/
   └─ home_panel.tscn
```

脚本建议：

```text
scripts/ui/
├─ gameplay_ui.gd                   # HUD、页面开关和状态协调
├─ components/
│  ├─ spirit_portrait_card.gd
│  └─ stat_meter.gd
├─ dex/dex_panel.gd                 # 图鉴数据绑定和筛选
└─ home/home_panel.gd               # 小屋选择、状态刷新和反馈
```

拆分期间由 `gameplay_ui.gd` 继续调用现有 `GameState`、`SaveManager` 和 `GameCatalog`，待页面稳定后再移除旧节点和旧路径。

## 8. 每个任务的固定执行循环

1. 读取本计划与目标页面现状。
2. 明确本次只修改一个任务编号。
3. 保存修改前截图或结构基线。
4. 实现最小范围改动。
5. 运行 `scripts/check-project.ps1`。
6. 按目标分辨率检查页面、关闭/返回和空状态。
7. 更新本文档任务状态与实际文件清单。
8. 通过验收后再进入下一个任务。

## 9. 总体验收标准

- 页面第一视觉焦点是萌灵、地图或当前行为，而不是大块文本面板。
- 图鉴和小屋不再使用文本 `ItemList` 作为主要导航。
- 所有主要页面均有明确的关闭方式，并支持统一返回输入。
- 正文和按钮文字在明亮地图背景上保持足够对比。
- UI 不通过半透明白色层反复叠加实现层次。
- 重要信息使用图标、卡片、徽章或进度条表达，长文本仅承担说明。
- 所有现有玩法、存档读取和数据源保持有效。
- 每个阶段通过项目检查并保留可对比的截图证据。

## 10. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 一次改动过大导致节点路径全面失效 | 新旧页面并存，独立页面验收后再删除旧节点 |
| UI 重构误改存档或玩法数据 | 页面只消费现有接口，不改存档字段和公式 |
| 缺少正式头像或图标 | 先使用现有萌灵素材生成缩略显示，不伪造拉伸皮肤 |
| 手机横屏空间不足 | P1 即建立响应式容器，不在封版阶段才补 |
| 视觉修改反复回退 | 每个任务保留截图基线与明确验收条件 |

## 11. 待确认事项

- 图鉴卡片后续是否需要独立正式头像资源，还是长期复用萌灵主立绘缩略图。
- 小屋中央萌灵首版使用静态图、现有战斗动画，还是单独制作小屋待机动画。
- 手柄按键规范将在输入架构稳定后补充，首版先保证鼠标、触控和 `Esc` 返回。
